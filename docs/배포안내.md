# 배포 안내 (처음 한 번)

GitHub 계정과 구글 계정이 있으면 30분 정도 걸립니다. 계정 만들기와 로그인은 직접 해 주세요.

## 1. GitHub 저장소 만들기
1. GitHub에 로그인 → 오른쪽 위 **+** → **New repository**
2. Repository name: 예) `contest` → 사이트 주소가 `https://{계정이름}.github.io/contest/`가 됩니다
3. **Public** 선택 (무료 GitHub Pages는 공개 저장소에서 동작) → **Create repository**
4. 이 프로젝트 폴더를 저장소에 올립니다. 이 PC에는 git이 없으므로 둘 중 편한 방법을 쓰세요.
   - **GitHub Desktop (권장):** [desktop.github.com](https://desktop.github.com)에서 설치 → File → Add local repository → 이 프로젝트 폴더 선택 → "create a repository" → Publish repository (Public 선택, 1~3번 대신 여기서 바로 만들어도 됩니다)
   - **웹에서 올리기:** 새 저장소 화면의 **uploading an existing file** → 프로젝트 폴더 안의 내용(`.github` 폴더 포함)을 끌어다 놓기 → Commit changes
     - `.github` 폴더가 빠지면 자동 실행이 되지 않습니다. 탐색기에서 숨김 항목 보기를 켜고 확인해 주세요.

## 2. GitHub Pages 켜기
저장소 → **Settings** → **Pages** → Build and deployment의 **Source**를 **GitHub Actions**로 선택

## 3. 구글 시트 만들기
1. `docs/구글시트_양식.xlsx`를 구글 드라이브에 올림 → 파일을 열고 **파일 → Google 스프레드시트로 저장**
2. 편집 권한은 운영자에게만 공유
3. **파일 → 공유 → 웹에 게시** → 탭을 하나씩 고르고(수정, 직접등록, 키워드, 수집사이트) 형식을 **쉼표로 구분된 값(.csv)** 으로 → **게시** → 나온 주소를 복사
   - 탭 4개라 주소도 4개입니다
   - 게시된 내용은 주소를 아는 사람은 누구나 볼 수 있으니 공개해도 되는 내용만 적어 주세요

## 4. 저장소에 설정값 넣기
저장소 → **Settings** → **Secrets and variables** → **Actions** → **Variables** 탭 → **New repository variable**

| 이름 | 값 |
|---|---|
| `CONTACT_EMAIL` | 사이트 하단과 수집기에 표시할 연락처 이메일 |
| `SHEET_EDIT_CSV` | '수정' 탭 CSV 주소 |
| `SHEET_ADD_CSV` | '직접등록' 탭 CSV 주소 |
| `SHEET_KEYWORDS_CSV` | '키워드' 탭 CSV 주소 |
| `SHEET_SITES_CSV` | '수집사이트' 탭 CSV 주소 |

사이트 주소(`SITE_URL`)는 저장소 이름으로 자동으로 정해지므로 넣지 않아도 됩니다.

**관리자 페이지 주소 (Secret으로 넣기):** 같은 화면의 **Secrets** 탭 → **New repository secret**
| 이름 | 값 |
|---|---|
| `ADMIN_PATH` | 관리자 페이지 주소로 쓸 영어·숫자 조합. 남이 짐작하기 어렵게 (예: `kanri-7f3k9q2`) → 관리자 페이지는 `https://{계정이름}.github.io/{저장소이름}/kanri-7f3k9q2/` |

저장소가 공개라서 Variables 대신 Secret에 넣습니다 (실행 기록에 값이 가려짐). 넣지 않으면 주소가 `/admin/`이 됩니다.

## 5. 첫 실행
저장소 → **Actions** → **공모전 수집·배포** → **Run workflow** → 몇 분 뒤 `https://{계정이름}.github.io/{저장소이름}/`에서 확인

이후에는 매일 08:00, 18:00(한국 시간)에 자동으로 수집·배포됩니다.

## 관리자 페이지에서 처리하기 (권장)
관리자 페이지에서 버튼으로 승인·숨김·확인을 누르면 저장소의 `data/decisions.json`에 저장되고, 1~2분 뒤 사이트에 반영됩니다.

**처음 한 번: GitHub 토큰 만들기** (관리자가 쓰는 기기마다 한 번씩 연결)
1. GitHub 오른쪽 위 프로필 사진 → **Settings** → 왼쪽 맨 아래 **Developer settings**
2. **Personal access tokens → Fine-grained tokens → Generate new token**
3. Token name: `contest 관리자` / Expiration: 원하는 기간 (만료되면 다시 만들어 연결)
4. Repository access: **Only select repositories** → `contest` 선택
5. Permissions → Repository permissions → **Contents: Read and write** (다른 권한은 그대로)
6. **Generate token** → 나온 값(`github_pat_…`)을 복사 → 관리자 페이지 맨 위 칸에 붙여넣고 **연결**

토큰은 그 기기의 브라우저에만 저장됩니다. 공용 PC에서는 다 쓴 뒤 **연결 해제**를 눌러 주세요.
토큰이 없는 사람은 관리자 주소를 알아도 버튼을 눌러 저장할 수 없습니다.

**버튼**
| 목록 | 버튼 | 결과 |
|---|---|---|
| 승인 대기 (경쟁사 관련) | 승인 | 사이트에 발행 |
| | 숨김 | 계속 비공개 |
| | (아무것도 안 누름) | 보류 — 그대로 대기 |
| 확인 필요 | 확인 | '확인 필요' 표시만 지움 |
| | 숨김 | 사이트에서 내림 |
| 처리 내역 | 되돌리기 | 결정을 취소 (원래 상태로) |

여러 개를 누른 뒤 아래 **반영하기**를 한 번 누르면 한꺼번에 저장됩니다. 마감이 지난 공모전은 목록에서 자동으로 사라집니다.

## 직원별 문의 링크
관리자 페이지 **직원 관리**에서 직원을 추가하면, 직원마다 `https://{사이트}/?ref=코드` 형태의 개인 링크가 생깁니다.

| 칸 | 내용 |
|---|---|
| 이름 | 사이트에 "담당 ○○○"으로 표시 (예: `김OO 선생님`) |
| 코드 | 영어 소문자·숫자 2~20자, 직원끼리 겹치면 안 됨 (예: `kim`, `lee2`) |
| 포트폴리오 상담 폼 | "무료 포트폴리오 상담" 버튼이 여는 네이버 폼 주소 (필수) |
| 공모전 문의 폼 | "공모전 준비 문의" 버튼이 여는 주소 (비우면 위 폼으로 연결) |
| 대표 문의 | 직원 코드 없이 들어온 학생이 연결될 곳 (비우면 버튼 숨김) |

- 직원 링크로 들어온 학생에게는 화면 아래에 **담당 ○○○ · 무료 포트폴리오 상담 · 공모전 준비 문의** 버튼이 보입니다.
- 학생이 공유 문구·필터 링크·주소창 주소를 친구에게 보내도 담당 직원 코드가 함께 따라갑니다.
- **담당 직원은 학생이 지금 연 링크의 코드로 정해집니다.** 다른 직원 링크를 열면 그 직원으로 바뀝니다. 같은 탭 안에서 목록↔상세를 오갈 때는 유지되고, 탭을 닫으면 기억하지 않습니다 (코드 없는 주소로 다시 들어오면 대표 문의).
- 직원을 삭제하면 그 링크로 들어온 학생은 대표 문의로 연결됩니다.
- 직원마다 **링크 복사**와 **QR**(이미지 저장) 버튼이 있어 전단지·게시물에 쓸 수 있습니다.
- 직원 정보를 바꾼 뒤 **반영하기**를 누르고 1~2분 지나야 새 링크가 동작합니다.
- 네이버 폼에는 개인정보 수집·이용 동의 항목을 꼭 넣어 주세요. 만 14세 미만은 법정대리인 동의가 필요합니다.

## 평소 운영
| 하고 싶은 일 | 방법 |
|---|---|
| 잘못 분류된 공모전 고치기 | 사이트 상세 페이지에서 **ID 복사** → 구글 시트 '수정' 탭에 붙여넣고 고칠 칸만 적기 |
| 공모전 숨기기 | '수정' 탭에 ID를 적고 숨김 칸에 `O` |
| 수집 안 된 공모전 추가 | '직접등록' 탭에 한 줄 추가 (제목·마감일 필수) |
| 관리자 페이지 | 사이트 주소 뒤에 `ADMIN_PATH`로 정한 값 (예: `/kanri-7f3k9q2/`) — 승인 대기, 확인 필요, 시트 경고, 최근 수집 현황 |
| 경쟁사 등록 | 시트 '키워드' 탭 종류 `경쟁사` 줄의 키워드 칸에 학원 이름을 쉼표로 (예: `○○아카데미, △△학원`) — 띄어쓰기·대소문자 무시 |
| 경쟁사 관련 공모전 승인 | 관리자 페이지 '승인 대기'에서 **승인** / **숨김** 버튼 → **반영하기** (시트 '수정' 탭 승인 칸에 적어도 됨) |
| 확인 필요 처리 | 관리자 페이지 '확인 필요'에서 **확인** / **숨김** 버튼 → **반영하기** |
| 고친 내용 바로 반영 | Actions → **Run workflow** → "새로 수집할까요?" 체크 해제 → 실행 (1~2분) |
| 수집이 잘 되는지 보기 | Actions 화면의 실행 기록, 또는 저장소의 `data/crawl_log.json` |

## 프로그램을 고친 뒤 GitHub에 다시 올리기
기능을 고치거나 추가하면 바뀐 파일을 저장소에 다시 올려야 사이트에 반영됩니다.
1. 저장소 첫 화면 → **Add file → Upload files**
2. 이 폴더에서 **`.github`, `.claude`, `data`를 뺀 나머지**(contesthub, config, docs, site, tests, tools 폴더와 README.md, requirements.txt 등)를 전부 끌어다 놓기 — 같은 이름의 파일은 새 내용으로 덮어써집니다
   - **`data` 폴더는 올리지 마세요.** GitHub 쪽 `data`에는 자동 수집 결과와 관리자 페이지에서 저장한 결정·직원 정보가 계속 쌓이고 있어서, 이 PC의 오래된 `data`로 덮어쓰면 그 내용이 지워집니다.
3. **Commit changes**
4. 올리면 자동으로 사이트가 다시 만들어집니다 (Actions 탭에서 진행 확인)

`.github` 폴더 안의 파일이 바뀐 경우에는 따로 안내드립니다 (웹 업로드가 이 폴더를 빠뜨리기 때문).
자주 고치게 되면 GitHub Desktop을 설치해 두는 것이 편합니다 — 바뀐 파일만 골라서 버튼 한 번으로 올라갑니다.

## 참고
- GitHub는 저장소에 60일 동안 변경이 없으면 예약 실행을 멈출 수 있습니다. 수집 결과가 매번 저장소에 저장되므로 보통은 문제없지만, 멈췄다면 Actions 화면에서 다시 켜면 됩니다.
- 예약 실행은 GitHub 사정에 따라 수십 분 늦게 시작될 수 있습니다.
- 일부 사이트가 GitHub 서버(해외)의 접속을 막으면 그 사이트만 수집이 0건으로 기록되고, 나머지로 사이트는 정상 갱신됩니다. 이 경우 사이트 이름의 날짜도 마지막으로 수집에 성공한 날짜로 유지됩니다.
